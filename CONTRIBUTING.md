# Contributing

Thanks for helping. This is a browser viewer and editor for .xlsx files written in plain JavaScript (ES modules, no
framework, no TypeScript build step).

## Setup

```sh
npm install
npm test            # unit tests in Node: reading, round trips, unit conversions
npm run lint        # ESLint: mistakes (unused or undefined names), not formatting
npm run dev         # demo at http://localhost:8080 (drag an .xlsx onto it)
npm run test:e2e    # Chromium: open, scroll and save each fixture, edit by keys and mouse, accessibility in light and dark
node tools/check-ooxml.mjs test/fixtures test/out   # structural check of the fixtures and the files the tests saved
```

The browser tests need Node 20 or later (Playwright) and a Chromium: `npx playwright install chromium`, or point
`CHROMIUM_PATH` at an installed Edge or Chrome.
CI (`.github/workflows/ci.yml`) runs all of the above on every push and pull request.

## Where things are

- `docs/ARCHITECTURE.md`: a map of every module. Start there.
- `docs/LAYOUT.md`: how layout is matched to Excel, the rules found and what was tried and dropped. Read it before
  changing how columns, rows or cell text are placed.
- `LESSONS.md` and `CLAUDE.md`: what the sister project (open-docx-editor) taught, and the rules that follow from it.

## How the code is written

- **Keep what isn't understood.** Every package part is kept byte for byte; only the parts the user changed are
  rewritten, and anything in such a part the editor doesn't model stays in place as it came in.
- **View state is not workbook content.** Selection, scroll and the like never reach the saved file.
- **Comments say why.** What Excel does and the measurement that showed it, not what the next line does. Refer to a
  private test workbook by its label (`sample X014`), never by its name.
- **One concern per change**, with a test where one fits: `test/*.test.js` for reading and saving, the browser suites
  (`test/*.mjs`) for what needs a page.
- Match the surrounding code: naming, comment density, two-space indents (`.editorconfig`), lines to about 120
  characters.

## Changing layout

Layout is measured against Excel's own PDFs, never another program's output. Keep a change only if the total doesn't
get worse and every workbook that got worse is understood, and add the rule it establishes to `docs/LAYOUT.md`.

## Saved files

Saved files must open in Excel without repair: run `tools/check-ooxml.mjs` on what you saved, and for anything new in
the format, open the saved file in Excel itself.

## Test workbooks

Fixtures in `test/fixtures` are generated by `test/fixtures/make-fixtures.mjs` (`npm run fixtures`), so the
repository holds no third-party workbooks. Please don't add real-world workbooks, Microsoft fonts or templates; describe
what a workbook needs and generate one instead.
